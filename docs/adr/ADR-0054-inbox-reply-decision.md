# ADR-0054: پاسخ inbox در فاز ۵ «ثبت رسیدگی» است، نه ارسال متن آزاد

- وضعیت: ACCEPTED
- تاریخ: 2026-09-23
- موج: ۳ فاز ۵ (بستن D14 / پرسش باز ۱ `PHASE-5AB-REVIEW.md`)

## زمینه

صفحه‌ی inbox از ابتدا یک textarea «پاسخ» داشت که دکمه‌ی ارسالش متن آزاد را
**هیچ‌جا نمی‌فرستاد**: قرارداد `PATCH /aftercare/inbox/:id` فقط
`{state, intent}` می‌پذیرد و endpoint ارسال پاسخ وجود ندارد. کاربر متنی
می‌نویسد، «ارسال» می‌زند، متن دور ریخته می‌شود و فقط state به `replied`
می‌رود — دقیقاً همان «گرفتنِ متن و دور ریختنِ آن» که سند بدهی (D14/Q1)
مشخص کرده بود.

دو راه حل از پرسش باز ۱: (الف) composer = ارسال قالب‌دار از router،
(ب) دکمه‌ی «رسیدگی شد» بدون متن آزاد.

## تصمیم

**گزینه‌ی (ب): دکمه‌ی «رسیدگی شد».** textarea و state آزادِ متن حذف می‌شود.
دکمه فقط `PATCH` با `{state: "replied"}` می‌زند و همان label صادق را دارد.
خروجی مرور شده در inbox سمت بیمار وجود ندارد که بخواهد به آن «پاسخ» بچسبد —
پس «پاسخ» قولی است که در این نسخه هیچ مسیر تحویلی ندارد.

## چرا این گزینه

1. **صداقت قرارداد**: هر متنی که امروز ارسال می‌شد باید مسیر `message_log` →
   آداپتور → تحویل → audit داشته باشد؛ این یعنی یک flow دومِ موازی با موتور
   aftercare، بدون ماتریس ایران، بدون سهمیه و بدون ردیابی — انحراف اسکوپ
   همان چیزی است که موج‌ها برایش مرز کشیده‌اند.
2. **پیام‌های خروجی باید قالب‌دار باشند** (قاعده‌ی PHI/لحن/ماتریس ایران).
   متن آزادِ کارشناس پشت همین ابهامِ قانونی ماندن است؛ این تصمیم آن ابهام را
   حذف می‌کند، نه پنهان.
3. **گزینه‌ی (الف) هنوز بسته نیست**: اگر بعداً لازم شد کارشناس پاسخ واقعی
   بفرستد، مسیر درست همان قالب‌های موجود (`aftercare.day1` و …) از طریق
   enqueue توسط موتور است؛ این ADR مانع آن نیست، فقط ادعای دروغ امروز را
   حذف می‌کند.

## پیامدها

- UI: textarea به دکمه‌ی «رسیدگی شد» تبدیل می‌شود؛ i18n کلیدهای جدید.
- API: بدون تغییر — همان `PATCH` معتبر.
- تست: تست UI دیگر «sending» را ادعا نمی‌کند.
- آینده: اگر پاسخ قالب‌دار لازم شد، موتور aftercare مسیرش را دارد؛ این ADR
  آن‌وقت با ADR جدید جایگزین/تکمیل می‌شود.
