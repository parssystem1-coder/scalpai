# راهنمای انتشار (Release Runbook) — موج ۳ / O1 + O4

این سند توضیح می‌دهد چطور یک نسخهٔ جدید ScalpAI منتشر می‌شود، زنجیرهٔ
به‌روزرسانی خودکار چطور کار می‌کند، و امضای کد ویندوز چطور فعال می‌شود.

## ۰) قدم اول (یک‌بار): فعال‌سازی ورک‌فلوها

توکن عامل خودکار (GitHub App) مجوز `workflows` ندارد و GitHub پوش مستقیم
فایل workflow را رد می‌کند — همان الگوی موج ۱. به همین دلیل دو فایل آماده در
`docs/release-pipeline/` قرار گرفته‌اند و مالک مخزن فقط یک‌بار این دو کپی را
روی ماشین خودش انجام می‌دهد (کامیت مالک مجوز لازم را دارد):

```bash
cd /d/FATEMEH/scalpai
git pull
cp docs/release-pipeline/release.yml .github/workflows/release.yml
cp docs/release-pipeline/ci.yml      .github/workflows/ci.yml   # نسخهٔ کامل جایگزین — ۳ گیت تست موج ۳ اضافه می‌کند
git add .github/workflows/ && git commit -m "ci: فعال‌سازی ورک‌فلوی ریلیز و گیت‌های تست موج ۳" && git push
```

> فایل `docs/release-pipeline/ci.yml` نسخهٔ **کامل** جایگزین است (نه وصله)؛
> در صورت تغییر دستی ci.yml در آینده، diff را قبل از کپی مقایسه کنید.

## ۱) زنجیرهٔ انتشار خودکار

```
git tag v1.1.0 && git push origin v1.1.0
        │
        ▼
.github/workflows/release.yml  (windows-latest)   ← پس از فعال‌سازی §۰
  ├─ check-changelog-version.cjs  → تگ = package.json = مدخل CHANGELOG.md
  ├─ test-build-assets.cjs        → آیکون‌ها/دارایی‌ها معتبرند
  ├─ build:assets + build         → renderer production
  └─ electron-builder --win --publish always
        │
        ▼
GitHub Releases: ScalpAI-1.1.0-win-x64.exe + portable + latest.yml
        │
        ▼
electron-updater در کلاینت‌ها: خواندن latest.yml → دانلود → بنر → ری‌استارت
```

- منبع انتشار در `electron-builder.json` (`publish`) پیکربندی شده: مخزن عمومی
  `parssystem1-coder/scalpai` — چون عمومی است، آپدیتر بدون توکن هم کار می‌کند.
- رفتار در dev: کنترلر (`electron/updater.cjs`) کاملاً stub است (بدون چک شبکه).
- رفتار در نسخهٔ نصب‌شده: چک خودکار ۱۵ ثانیه بعد از لانچ (با `unref` تا خروج اپ
  گیر نکند) + بنر فارسی/انگلیسی وقتی آپدیت دانلود شد. نصب فقط با کلیک کاربر.

## ۲) قواعد نسخه‌گذاری (semver)

1. قبل از تگ: نسخهٔ `package.json` را بالا ببرید و مدخل متناظر در `CHANGELOG.md`
   بنویسید — نگهبان `scripts/check-changelog-version.cjs` (در CI و انتشار) بدون
   این دو اجازه نمی‌دهد.
2. تگ‌ها به شکل `vX.Y.Z` و از روی آخرین گرنی سبز CI.
3. هرگز ریلیز را «ویرایش نکنید»؛ اگر باگی درآمد، نسخهٔ جدید (patch) منتشر کنید —
   تغییر asset ریلیز، کاربرانی که دانلود کرده‌اند را با checksum خراب رها می‌کند.

## ۳) امضای کد ویندوز (O4)

### وضعیت امروز (صادقانه)
نصب‌کننده **بدون امضا** منتشر می‌شود. پیامدها:
- هنگام نصب/به‌روزرسانی، ویندوز SmartScreen آبی («Windows protected your PC»)
  نشان می‌دهد تا کاربر «Run anyway» بزند. با گذر زمان و افزایش reputation، این
  هشدار برای امضاهای معتبر کم‌رنگ می‌شود — برای بیلدهای امضانشده باقی می‌ماند.
- به‌روزرسانی خودکار همچنان کار می‌کند (دانلود + اطلاع)، ولی نصب آپدیت هم همان
  SmartScreen را دارد؛ کاربر باید تأیید کند.

### فعال‌سازی امضا
۱) خرید گواهی Code Signing:
   - **OV** (~۲۵۰–۴۰۰ دلار/سال): SmartScreen تا رسیدن به reputation اولیه باقی است.
   - **EV** (~۴۰۰–۷۰۰ دلار/سال): reputation فوری؛ همراه USB token/ZTP.
   برای کلینیک و توزیع عمومی، EV توصیه می‌شود.
۲) تبدیل گواهی به `base64` یک فایل `.pfx`:
   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("cert.pfx")) | Out-File cert.b64.txt
   ```
۳) در GitHub: Settings → Secrets and variables → Actions:
   - `CSC_LINK` = محتوای base64 (یک خط، بدون فاصله اضافی)
   - `CSC_KEY_PASSWORD` = پسورد فایل pfx
۴) ورک‌فلوی release به‌صورت خودکار امضا می‌کند (envها از قبل پاس داده شده‌اند؛
   timestamp digicert هم در `electron-builder.json` هست: `rfc3161TimeStampServer`).
۵) ریلیز بعدی را تست کنید: دانلود → نباید هشدار قرمز «ناشناس» بیاید (آبی اولیه
   برای OV طبیعی است).

> بدون سکرت‌ها، بیلد بدون امضا می‌شود و workflow خطا نمی‌دهد — این رفتار
> آگاهانه است تا انتشار هرگز به‌خاطر نبود گواهی نایستد.

## ۴) چک‌لیست E2E به‌روزرسانی روی ویندوز واقعی (DoD موج ۳)

این چک‌لیست روی ماشین ویندوز با اینترنت انجام می‌شود (سمت کاربر/آرنا قابل اجرا
نیست):

1. نسخهٔ قدیمی‌تر را نصب کنید (مثلاً v1.1.0).
2. تگ `v1.1.1` با یک تغییر قابل‌مشاهده (مثلاً متن دربارهٔ ما) بزنید تا ریلیز ساخته شود.
3. اپ v1.1.0 را باز کنید و ~۲۰ ثانیه صبر کنید → بنر «نسخهٔ جدید در حال دانلود…»
   و بعد «به‌روزرسانی دانلود شد» باید ظاهر شود.
4. «ری‌استارت و نصب» → نصب‌کننده اجرا می‌شود و اپ با نسخهٔ ۱.۱.۱ بالا می‌آید.
   - در بیلد امضانشده، SmartScreen باید با «Run anyway» رد شود (مستند در بالا).
5. نسخهٔ جدید را در پایین پنجرهٔ اصلی/صفحهٔ About ببینید؛ داده‌ها (مشتریان،
   تصاویر، مدل) دست‌نخورده باقی مانده‌اند.
6. (اختیاری) `app-update.yml` در resources نسخهٔ نصب‌شده را باز کنید — باید به
   مخزن `parssystem1-coder/scalpai` اشاره کند.

## ۵) بکاپ فایل‌محور (مرجع سریع O2/O3)

- خروجی و بازیابی دستی: تنظیمات → «پشتیبان/بازیابی». دیالوگ و ساخت ZIP هر دو در
  main انجام می‌شود (بدون عبور payload باینری از IPC).
- بکاپ خودکار روزانه: `userData/auto-backups/` — حداکثر ۵ نسخهٔ آخر نگه داشته
  می‌شود (همان رفتار قبل، ولی با استریم فایل‌محور).
- مدل محلی: تیک «مدل محلی AI هم داخل بکاپ قرار گیرد» → `model.json` +
  `model.weights.bin` داخل ZIP؛ در بازیابی «چلنجر» می‌شود.
- تست پروفایل حافظه (۵۰۰۰ تصویر): `pnpm run test:backup-stream` — دلتا heap باید
  کوچک‌تر از ۴۰MB بماند در حالی که آرشیو بزرگ‌تر از ۱۵MB است.
